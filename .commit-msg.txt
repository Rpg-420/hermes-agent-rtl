i18n: translate the full 5,065-key catalog

The pack covered 88 of the app's 5,065 strings. This takes it to all of them.

Structure changed so the pack is data, not code. The 106-line `const FA = {...}`
object came out of plugin.template.js (build/split_fa_block.py, idempotent, with
a backup) and its place is a __FA_PACK__ placeholder that build.py fills from
build/fa.pack.json. The Persian strings now live in build/fa_fragments/*.json,
one file per section-group, keyed by the flattened en.ts dot-path.

Two new build scripts:

  merge_fa.py          9 fragments -> fa.pack.json, asserted against the catalog
  merge_fa_partial.py  same merge, coverage gate relaxed, for build-path testing

merge_fa.py refuses to write on three things, because each of them fails
silently otherwise:

  - an unknown key. This is the one that matters: registerAppLocale merges over
    the catalog, so a mistyped dot-path is never an error to the app -- it is a
    string that never renders, forever. The build turns that into a failure.
  - a key still equal to its English.
  - a {0} placeholder in a Persian string whose English entry is a plain string,
    so there is no argument to interpolate and it renders literally.

660 of the keys have a function as their English entry (interpolators, plurals).
Those are written as positional {0}/{1} strings, which the SDK's merge wraps
back into the same call shape -- documented, and now covered rather than skipped.

Fixed 35 strings the first pass left in English: UI labels (Pets, Gateway,
Clipboard, Cron, Bots, URL, CVC) plus the font sample, which now uses the
Persian pangram instead of the English one. Product names, URLs, code
identifiers and the you@example.com placeholder stay verbatim by design and are
allowlisted with a reason.

harness/i18n.test.mjs had a rule that formatter keys must NOT be translated --
written when the pack skipped functions on purpose, and now wrong. It now asserts
the opposite failure mode: a positional rewrite that invented placeholders the
English never passes. The bar is 4 slots; a pagination range legitimately takes
three ('{0} تا {1} از {2}').

Verified: merge_fa.py reports 5065/5065 with no unknown, untranslated or
bad-placeholder keys; the built module loads and register() runs; atfix 8 passed;
i18n reports 5065 keys, all resolving.
